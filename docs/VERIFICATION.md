## 实体模式同步修复（1.2.3）

此前定时刷新仅更新亮度／音量，实体菜单更改模式时不会触发亮度能力复查。现已补上面板打开时每 5 秒同步画面设置，并仅在已观察到的模式编号发生变化时重新检查亮度。若有读取或写入正在执行，复查会延后；更新的键盘／滑块操作优先于旧读取和旧复查。显式的软件调光偏好保持不变。

`bash scripts/test.sh` 中新增假 DDC 和无屏幕遮罩的测试，覆盖延后复查、自动模式恢复硬件、软件调整与读回竞态、显式软件偏好。它们是模型回归测试，不是新的实体模式切换实测；本轮未改动用户显示器模式。安装后已通过 cua_repl 核对 1.2.3 版本标识、常用／画面页和当前游戏模式下的两个并列设置。观察到面板打开期间运行状态自动刷新；辅助功能与媒体键监听保持有效。证据：`build/mode-sync-verification-1.2.3.json`。

## 两个菜单的结构修正

用户照片及最新说明确认「图像模式」与「低蓝光」是两个菜单，各图像模式下均能进入低蓝光菜单。1.2.2 将它们并列显示，主模式列表只保留单个低蓝光选项，四个场景单独显示。当前协议只确认四个场景编号的读写，未证明与游戏、sRGB 等模式可独立组合；界面明确提示切换可能改变图像模式，不把历史场景记忆显示为当前硬件状态。模型测试覆盖主列表去重、已确认场景记忆及写失败回退。

## sRGB／Rec.709 的结论修正

用户逐一确认的两个模式都返回主编号 12。两轮多参数快照曾显示 0x14 分别为 11／12，但进一步只读实验发现该字段会复制前一个离散参数的当前值：先读取比例便返回 5，先读取模式便返回 12，再读比例又返回 5。

该“区分参数”结论已撤回，未安装到产品。完整报文和研究过程见 `PROTOCOL.md` 及 `build/protocol-snapshots/color-aspect-order.txt`。界面使用 **sRGB / Rec.709** 共用项，明确不能独立切换。HDR／影院 HDR 和 B.I.+ 尚无可靠软件控制，不声称已经支持。

## 已安装应用的自动测试与限制

旧版本的公开 URL 测试曾通过软件亮度、音量和静音恢复。新版测试期间收到了用户的真实按键，预期亮度与用户调整冲突，故 `build/runtime-smoke-test.json` 本次标记为 **inconclusive / interruptedByKeyboard**，不能算作新版全流程通过。脚本已修正：检测到键盘操作即停止，并避免继续恢复旧值覆盖用户操作。

早先界面自动化工具连续返回 `Sky Computer Use native pipe startup failed`。随后通道恢复，已用 cua_repl 检查安装版三页导航、下拉选项和授权显示，实测 Control+Option+B 打开面板。在当前游戏模式下，低蓝光四个入口仍显示。首次切页后出现一次 noWindowsAvailable，重新用快捷键打开后页签状态已切换，后续导航正常。证据记录：`build/live-ui-verification-1.2.2.json`。本次仅验证导航和可见状态，没有改变亮度、音量、图像模式；不据此声称独立低蓝光组合或每个控件写入均通过。

登录启动提供系统 SMAppService 开关，但未实际重启／注销用户会话进行测试。多显示器、不同线缆、睡眠／唤醒和拔插场景未进行完整现场验证，不将已有恢复代码称为覆盖这些场景的实测。
